# Prototype Scope Guide

## 核心原则

> **原型的目标是验证假设，不是做游戏。**

每个原型必须回答一个明确的问题：
- "这个移动手感对吗？"
- "这个战斗循环有趣吗？"
- "这个相机角度能看清战场吗？"

## 从 GDD 提取原型范围

### Step 1: 提取核心假设

读取 `GDD/02-gameplay/01-player-mechanics.md`，找到核心动词：
- 移动 → 需要 PlayerController + Camera
- 攻击 → 需要 CombatSystem + Enemy
- 收集 → 需要 Inventory + Pickup
- 对话 → 需要 DialogueSystem + NPC
- 建造 → 需要 BuildingSystem + Grid

**只做优先级最高的 1-2 个动词。**

### Step 2: 提取最小关卡

读取 `GDD/03-level-design/02-level-one-pagers/`，选第一个关卡/教学关。
只做：
- 地面/平台（Plane/Cube）
- 必要的墙壁/障碍
- 1-2 个敌人点位
- 起点和终点

不做：
- 装饰/植被/灯光细节
- 多条路径
- 隐藏区域
- 过场动画触发点

### Step 3: 提取最小 UI

读取 `GDD/04-ui-ux/01-hud-wireframes.md`，只做：
- 生命值/体力值（如 GDD 有此机制）
- 分数/进度（如核心循环依赖）
- 交互提示（如需要按键提示）

不做：
- 主菜单
- 设置面板
- 背包界面
- 对话 UI（用 Debug.Log 替代）

### Step 4: 决定资产策略

**原型阶段全部使用占位资产：**
| 需求 | 占位方案 |
|------|----------|
| 角色 | Capsule + 彩色材质 |
| 敌人 | Cube + 红色材质 |
| 道具 | Sphere + 黄色材质 |
| 地面 | Plane + 灰色材质 |
| 墙壁 | Cube + 深灰材质 |
| 特效 | Debug.DrawLine / 空GameObject |
| 音频 | 无（除非核心验证需要） |
| UI | 默认 TMP 文本 + 白色 Panel |

## 原型类型决策树

```
GDD 中最不确定的是什么？
├── 操作手感 ──→ 原型：PlayerController + 训练场关卡
├── 战斗系统 ──→ 原型：CombatSystem + 竞技场关卡 + 1 种敌人
├── AI 行为 ──→ 原型：EnemyAI + 测试关卡 + 多种地形
├── 物理/碰撞 ──→ 原型：PhysicsTest + 障碍物关卡
├── 相机系统 ──→ 原型：CameraTest + 多地形关卡
├── UI/UX 流程 ──→ 原型：UI_Flow + 只做 UI 场景
├── 程序化生成 ──→ 原型：ProcGen + 可视化调试
└── 多个不确定 ──→ 做 2-3 个小原型，每个专注一个方面
```

## 原型完成标准

原型达标时，应满足：
1. 核心循环可在 30 秒内体验（从启动到完成一次循环）
2. 不需要教程就能理解操作（或只需一句提示）
3. 帧率不卡顿（允许未优化的 30fps）
4. 能回答最初的那个验证问题

## 反模式（NOT to do）

- 不要一上来就做完整的角色控制器（先做移动+跳跃，后续再加）
- 不要导入美术资源（灰盒阶段用 Primitive 就够了）
- 不要做菜单系统（直接在场景里开始）
- 不要写超过 100 行的单个脚本（太复杂说明范围太大）
- 不要做网络同步（原型阶段单机即可）
- 不要做存档/读档（每次重新开始）
