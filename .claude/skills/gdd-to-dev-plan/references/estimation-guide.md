# Estimation Guide

## 估算原则

1. **以「人天」为单位**，1 人天 = 1 名全职开发者 1 天的工作量
2. **包含测试与联调时间**，不光是写代码/做资产的时间
3. **区分不确定度**：
   - 高确定性（已有参考/经验）：±20%
   - 中确定性（需要探索/验证）：±50%
   - 低确定性（新技术/新领域）：标注 `> 💡 高不确定度，建议做 Spike`
4. **取最可能值 + 最坏值**，不做盲目乐观估计

## 常见调整因子

| 情况 | 系数 | 说明 |
|------|------|------|
| 团队已有该类型经验 | ×0.7 | 少走弯路 |
| 使用不熟悉的引擎/工具 | ×1.5 | 学习成本 |
| 需要跨团队协调 | ×1.3 | 沟通开销 |
| 外包/远程协作 | ×1.4 | 时差与沟通 |
| 已有可复用的框架/资产 | ×0.5 | 省去从零开始 |
| 需要通过平台认证 | ×1.2 | 认证返工 |

## 团队规模估算参考

基于总人天数反推团队配置：
- 总人天 ÷ 可用工作日 = 所需并行人数
- 例如：1000 人天 ÷ 200 工作日 ≈ 5 人核心团队
- 注意各类职能不能互相替代（你不能用 3 个美术替代 1 个程序）

## 估算输出格式

在任务列表中每个任务都标注：
```
| 任务 | 职能 | 工时 | 不确定度 | 依赖 |
|------|------|------|----------|------|
| 实现背包系统 | 程序 | 8-12d | 中 | 物品数据结构已完成 |
| 制作 5 个敌人模型 | 美术 | 25-75d | 中 | 概念设计完成 |
```
